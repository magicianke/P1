# CLAUDE.md

## Язык общения
Всегда отвечай пользователю **по-русски**. Комментарии в коде — тоже по-русски; идентификаторы, имена файлов и коммиты — латиницей.

## О проекте
CAN-бус ридер и приборная панель на **ESP32-S3** с **3.5" дисплеем**, встроенным в **левый дефлектор (слева от руля)**.

### Автомобиль
- **Subaru Impreza GH** (2007–2011), **2.0 атмо** (EJ20, без турбо).
- **АКПП 4-ст., TZ1** (4EAT), гидротрансформатор с блокировкой.
- **Левый руль.** Дефлектор находится у левой двери, рядом с комбинацией приборов: экран должен читаться боковым взглядом, без отвлечения от дороги.

### Подключение к CAN
- Разъём OBD-II: **CAN-H — pin 6, CAN-L — pin 14**, GND — pins 4/5, +12 В (постоянно) — pin 16.
- Скорость шины **500 кбит/с**, 11-битные ID (проверить снифером на конкретной машине).
- Контроллер: встроенный **TWAI** ESP32-S3 + 3,3-вольтовый трансивер (SN65HVD230 / TJA1051T/3 или аналог).
- Питание: 12 В → DC-DC 5 В, с защитой (TVS, предохранитель, защита от переполюсовки). Учитывать просадки при прокрутке стартером и выбросы до ~40 В. Питание лучше брать от ACC, чтобы не сажать аккумулятор.

## Правила безопасности (важно)
1. **По умолчанию TWAI работает в режиме `LISTEN_ONLY`.** Устройство не должно ничего передавать в шину и даже не отправлять ACK.
2. Активные запросы (OBD-II Mode 01, Subaru SSM для данных АКПП) разрешены **только** через явный флаг конфигурации, с ограничением частоты (не чаще ~10–20 запросов/с суммарно) и только на диагностические ID (0x7DF / 0x7E0–0x7E7).
3. Никогда не пиши код, который шлёт произвольные фреймы на ID штатных блоков (ECU, TCU, ABS, BIU).
4. Сбой устройства не должен влиять на машину: при ошибках шины (bus-off, error passive) — переходить в пассивный режим и не переподключаться агрессивно.
5. UI не должен отвлекать: никаких анимаций ради анимаций; критичные предупреждения (перегрев ОЖ, перегрев ATF) — крупно и контрастно.

## Что показываем (приоритет)
1. Температура ОЖ.
2. **Температура ATF (масла АКПП)** — главная ценность для 4EAT: перегрев убивает коробку. Доступна через SSM-запросы к TCU, а не через стандартные OBD PID.
3. Текущая передача и состояние блокировки ГТ (lock-up) — если удастся найти в шине или через SSM.
4. Обороты, скорость, напряжение бортсети, IAT, нагрузка двигателя, мгновенный и средний расход (расчётный).
5. Чтение и сброс DTC — только как отдельная функция с подтверждением.

## Известное и неизвестное о шине
- CAN ID штатного обмена на GH **документально не подтверждены**. Любой ID из интернета (форумы, данные по GE/GR/BRZ) считать гипотезой до проверки снифером на этой машине. Подтверждённые ID фиксировать в `docs/can_ids.md` с датой, условиями проверки и формулой декодирования.
- Стандартные OBD-II PID (Mode 01: 0x05 ОЖ, 0x0C обороты, 0x0D скорость, 0x0F IAT, 0x04 нагрузка, 0x42 напряжение и др.) работают через 0x7DF → ответ 0x7E8.
- SSM-адреса параметров TCU (ATF temp и др.) — **проверить**, не выдумывать.

## Железо
- **ESP32-S3 DevKitC-1 (клон, 2× Type-C)**: «COM» — мост USB-UART, «USB» — нативный USB. Объём flash и PSRAM ещё не определены (`.\build.ps1 chipinfo`). Пока в сборке безопасные 4 МБ без PSRAM.
- **3.5" IPS ILI9488**, SPI, 320×480, тач (по умолчанию считаем резистивным XPT2046 — подтвердить по разъёму модуля). SDO дисплея не подключаем.
- **SN65HVD230DR** (SOIC-8), Rs → GND, без терминатора 120 Ом.
- Распиновка — `src/board_config.h`, схема — `docs/wiring.md`.

## Сборка
```powershell
.\build.ps1 compile            # проверка сборки
.\build.ps1 flash -Port COM5   # прошить и открыть монитор
.\build.ps1 chipinfo           # размер flash / PSRAM
```
`build.ps1` должен оставаться в **UTF-8 с BOM**, иначе Windows PowerShell 5.1 ломает кириллицу.
Структура скетча: arduino-cli компилирует корень и всё внутри `src/`, поэтому весь код лежит в `src/`, а `P1.ino` подключает его как `#include "src/..."`.

## Инструменты (на машине пользователя)
- **arduino-cli 1.4.1**, встроенный в Arduino IDE 2:
  `"%LOCALAPPDATA%\Programs\Arduino IDE\resources\app\lib\backend\resources\arduino-cli.exe"`
  (в PATH его нет).
- Ядро **esp32:esp32 3.3.11** (Arduino-ESP32 3.x, ESP-IDF 5.x). TWAI — через `driver/twai.h`.
- Библиотеки: **LovyanGFX 1.2.27**, GFX Library for Arduino 1.4.7, NimBLE-Arduino 2.5.0.
- PlatformIO **не установлен**, Python в системе не установлен (только заглушка Microsoft Store).
- Git установлен, но папка проекта пока не является репозиторием.

## Конвенции кода
- C++17, Arduino-ESP32 3.x. Никаких `delay()` в основном цикле, только задачи FreeRTOS и неблокирующая логика.
- Приём CAN — в отдельной задаче (ядро 0), UI — на ядре 1. Обмен через очередь или снапшот данных под мьютексом.
- Декодеры сигналов — чистые функции без зависимостей от железа, чтобы их можно было тестировать на ПК.
- Все пины и параметры железа — только в `src/board_config.h`.
- Единицы СИ внутри, форматирование — только в UI.
