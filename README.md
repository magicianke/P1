# P1 — CAN-дисплей для Subaru Impreza GH

Дополнительная приборная панель на **ESP32-S3** с **3.5" IPS-дисплеем**, встроенным в **левый дефлектор** (слева от руля). Устройство подключается к разъёму OBD-II, читает CAN-шину и показывает параметры, которых нет на штатной приборке. Главный из них — **температура масла АКПП**.

> **Статус:** этап 1. Работают дисплей и сниффер CAN (только прослушивание). На реальной машине пока не проверялось.

---

## Автомобиль

| | |
|---|---|
| Модель | Subaru Impreza GH (2007–2011) |
| Двигатель | 2.0 атмосферный (EJ20) |
| Коробка | АКПП 4-ст., **TZ1** (4EAT) |
| Руль | левый |
| Диагностика | OBD-II, CAN 500 кбит/с (pin 6 — CAN-H, pin 14 — CAN-L) |

**Почему температура масла АКПП.** 4EAT чувствительна к перегреву масла: в пробках, на подъёмах и при активной езде оно быстро стареет, и коробка изнашивается. Штатно эту температуру не показывают, а получить её можно только запросом к блоку АКПП по протоколу Subaru SSM.

## Возможности

### Готово
- Приём CAN на 500 кбит/с во встроенном контроллере **TWAI** ESP32-S3, в режиме **LISTEN_ONLY**: устройство ничего не передаёт в шину.
- **Экранный сниффер:** таблица всех CAN ID с данными, длиной и периодом прихода. Байты, изменившиеся за последнюю секунду, подсвечиваются жёлтым — удобно искать сигналы. Листание страниц: джойстик вправо/влево, а пока джойстик не подключён — кнопка BOOT.
- Статистика шины: кадров в секунду, потери в очереди, ошибки шины.
- **Лог в USB** в формате `candump -L`, открывается в [SavvyCAN](https://www.savvycan.com/) и can-utils.

### Планы
- [ ] Опрос стандартных OBD-II PID: температура ОЖ, обороты, скорость, IAT, нагрузка, напряжение.
- [ ] Запросы Subaru SSM к блоку АКПП: **температура масла АКПП**, текущая передача, блокировка гидротрансформатора.
- [ ] Расшифровка штатных кадров шины, найденных снифером (журнал в [`docs/can_ids.md`](docs/can_ids.md)).
- [ ] Основной экран для поездки: крупные цифры, читаются боковым взглядом.
- [ ] Предупреждения о перегреве ОЖ и масла АКПП.
- [ ] Чтение и сброс кодов ошибок (DTC), с подтверждением.
- [ ] Расчётный расход топлива.
- [ ] Автояркость или привязка подсветки к габаритам.
- [ ] Корпус и крепление в дефлектор.

## Железо

| Компонент | Модель | Примечание |
|---|---|---|
| Плата | P1 rev 1.0 (своя, EasyEDA) | схема и разводка в `docs/hardware/` |
| Контроллер | ESP32-S3-DevKitC-1 N16R8 | 16 МБ flash, 8 МБ OPI PSRAM |
| Дисплей | 3.5" IPS ILI9488, SPI, 320×480 | тач на плату не выведен |
| Управление | джойстик ALPS RKJXT1F42001 + потенциометр WH148 | гребёнка H1 |
| CAN-трансивер | SN65HVD230DR (SOIC-8) | питание 3,3 В |
| Питание | LM2596S-5.0, 12→5 В | защиты на плате нет, нужен внешний предохранитель |

Подробное описание платы, распиновка и известные проблемы ревизии — в [`docs/hardware.md`](docs/hardware.md). Это источник истины по железу.

### Подключение (кратко)

| Сигнал | GPIO |
|---|---|
| TFT SCK / MOSI / CS / DC / RST / подсветка | 10 / 11 / 14 / 12 / 13 / 9 |
| CAN TX (→ D трансивера) / RX (← R) | 41 / 21 |
| Джойстик UP / DOWN / LEFT / RIGHT / ENTER | 5 / 6 / 7 / 15 / 16 |
| Энкодер A / B, потенциометр | 17 / 8, 4 |

Памятка по подключению, включая питание и разъём OBD, — в [`docs/wiring.md`](docs/wiring.md). Распиновка в коде — только в [`src/board_config.h`](src/board_config.h).

⚠️ **Важно:**
- **SDO (MISO) дисплея не используется**: GPIO46 — strapping-пин.
- **Нельзя одновременно подавать 12 В и подключать USB**: оба источника 5 В встретятся на пине 5V.
- **Терминатор 120 Ом не ставить**: шина в машине уже терминирована.
- Rs (pin 8) трансивера — на GND.

## Безопасность

Устройство подключено к шине, по которой общаются двигатель, АКПП, ABS и другие блоки, поэтому действуют правила:

1. **По умолчанию только прослушивание.** Контроллер не передаёт кадры и даже не ставит ACK.
2. Активные запросы (OBD-II, SSM) включаются только явным флагом, с ограничением частоты и только на диагностические ID (`0x7DF`, `0x7E0`–`0x7E7`).
3. Никакой отправки кадров на ID штатных блоков.
4. Если устройство сломается или зависнет, на работу машины это не повлияет.
5. Интерфейс не отвлекает от дороги: без лишних анимаций, предупреждения крупные и контрастные.

## Сборка и прошивка

Используется **arduino-cli** с ядром **esp32:esp32 3.3.x** (Arduino-ESP32 3.x / ESP-IDF 5.x) и библиотекой **LovyanGFX**.

### Windows (основной компьютер)

arduino-cli берётся из комплекта Arduino IDE 2, отдельно ставить не нужно.

```powershell
.\build.ps1 compile            # сборка
.\build.ps1 upload  -Port COM5 # прошивка
.\build.ps1 monitor -Port COM5 # монитор порта (лог CAN)
.\build.ps1 flash   -Port COM5 # прошивка + монитор
.\build.ps1 chipinfo           # узнать объём flash и наличие PSRAM
```

Без `-Port` скрипт берёт первый найденный COM-порт. Подключаться к разъёму **«USB»** на плате.

Если система не даёт запускать скрипты:
```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1 compile
```

### Любая ОС (вручную)

```bash
arduino-cli core install esp32:esp32
arduino-cli lib install LovyanGFX
arduino-cli compile --fqbn "esp32:esp32:esp32s3:FlashSize=16M,PartitionScheme=app3M_fat9M_16MB,PSRAM=opi,USBMode=hwcdc,CDCOnBoot=cdc,CPUFreq=240" .
```

> Параметры сборки рассчитаны на модуль N16R8 (16 МБ flash, OPI PSRAM). Проверить модуль можно командой `.\build.ps1 chipinfo`.

### Если что-то не так с экраном
- **Цвета в негативе** — `kTftInvert = false` в `src/board_config.h`.
- **Изображение повёрнуто** — `tft.setRotation(...)` в `src/ui/display.cpp`.
- **Мусор или нестабильная картинка** — снизить `kTftSpiHz` в `src/board_config.h`.

В следующих этапах появятся `src/can/obd_poller.*`, `src/decode/` (OBD PID, SSM, кадры Subaru), `src/model/vehicle_state.h` и экраны в `src/ui/screens/`.

### Как устроена прошивка
- **Ядро 0:** задача `can_rx` принимает кадры из TWAI, обновляет таблицу ID (под мьютексом) и пишет лог в USB. Если USB не успевает, кадры в логе пропускаются и считаются (`drop`), но приём не тормозит.
- **Ядро 1:** `loop()` перерисовывает экран 5 раз в секунду по строкам через спрайт, без мерцания и без буфера на весь экран.

## Как искать сигналы

1. Прошить устройство и подключить его к OBD-II.
2. Подключить ноутбук к разъёму «USB» и записать лог: `.\build.ps1 monitor > log.txt`.
3. Делать по одному действию: зажигание, запуск, газ, переключение селектора P-R-N-D, тормоз, поворот руля. Смотреть, какие байты подсвечиваются на экране.
4. Разобрать лог в SavvyCAN.
5. Каждый подтверждённый сигнал записать в [`docs/can_ids.md`](docs/can_ids.md): ID, байты, формула, как проверено, дата.

Данные из интернета (форумы, другие модели Subaru) — только гипотезы, пока сигнал не проверен на этой машине.
